# Quick Setup Guide: Apache VPN Configuration

This is a condensed step-by-step guide. For detailed explanations, see [APACHE_VPN_SETUP_GUIDE.md](../APACHE_VPN_SETUP_GUIDE.md).

## Prerequisites

- Apache web server installed
- Node.js and npm installed
- Dependability Tracker application installed
- SSL/TLS certificates (self-signed or trusted)
- VPN access configured

## Step-by-Step Implementation

### 1. Install Apache (if not already installed)

**Ubuntu/Debian:**
```bash
sudo apt update
sudo apt install apache2
```

**RHEL/CentOS/Fedora:**
```bash
sudo yum install httpd
# or
sudo dnf install httpd
```

### 2. Enable Required Apache Modules

**Ubuntu/Debian:**
```bash
sudo a2enmod ssl
sudo a2enmod proxy
sudo a2enmod proxy_http
sudo a2enmod proxy_wstunnel
sudo a2enmod headers
sudo a2enmod rewrite
```

**RHEL/CentOS/Fedora:**
Edit `/etc/httpd/conf/httpd.conf` or `/etc/httpd/conf.modules.d/00-base.conf` and ensure these are uncommented:
```apache
LoadModule ssl_module modules/mod_ssl.so
LoadModule proxy_module modules/mod_proxy.so
LoadModule proxy_http_module modules/mod_proxy_http.so
LoadModule proxy_wstunnel_module modules/mod_proxy_wstunnel.so
LoadModule headers_module modules/mod_headers.so
LoadModule rewrite_module modules/mod_rewrite.so
```

### 3. Configure SSL Certificates

**Option A: Use Self-Signed Certificates (already generated by the app)**
```bash
cd /path/to/dependability-tracker
npm run genTLS
# Certificates will be in: cert/certificate.pem and cert/private_key.pem
# Use these paths in Apache config:
#   SSLCertificateFile /path/to/project/cert/certificate.pem
#   SSLCertificateKeyFile /path/to/project/cert/private_key.pem
```

**Option B: Use Let's Encrypt (requires public domain)**
```bash
# Ubuntu/Debian
sudo apt install certbot python3-certbot-apache

# RHEL/CentOS/Fedora
sudo yum install certbot python3-certbot-apache
# or
sudo dnf install certbot python3-certbot-apache

# Obtain certificate
sudo certbot --apache -d yourdomain.com
# Certificates will be in: /etc/letsencrypt/live/yourdomain.com/
```

**Option C: Use Corporate Certificates**
- Request certificates from your IT/security team
- Place them in a secure location (e.g., `/etc/ssl/private/`)
- Use appropriate file extensions (.crt, .pem, etc.)

### 4. Create Apache Virtual Host Configuration

**Ubuntu/Debian:**
```bash
sudo cp /path/to/dependability-tracker/examples/apache-vpn-reverse-proxy.conf \
        /etc/apache2/sites-available/dependability-tracker.conf
```

**RHEL/CentOS/Fedora:**
```bash
sudo cp /path/to/dependability-tracker/examples/apache-vpn-reverse-proxy.conf \
        /etc/httpd/conf.d/dependability-tracker.conf
```

### 5. Edit the Configuration File

```bash
# Ubuntu/Debian
sudo nano /etc/apache2/sites-available/dependability-tracker.conf

# RHEL/CentOS/Fedora
sudo nano /etc/httpd/conf.d/dependability-tracker.conf
```

**Customize these values:**
- `ServerName` → Your domain or VPN IP
- `SSLCertificateFile` → Path to your certificate
- `SSLCertificateKeyFile` → Path to your private key
- `Allow from 10.0.0.0/8` → Your VPN subnet
- `ProxyPass` port → Match your PORT in .env (default 3000)

### 6. Test Apache Configuration

```bash
# Ubuntu/Debian
sudo apache2ctl configtest

# RHEL/CentOS/Fedora
sudo apachectl configtest
```

Should output: `Syntax OK`

### 7. Enable the Site (Ubuntu/Debian only)

```bash
sudo a2ensite dependability-tracker.conf
```

### 8. Configure Firewall

**Ubuntu/Debian (UFW):**
```bash
sudo ufw allow 443/tcp
sudo ufw allow 'Apache Full'
sudo ufw reload
```

**RHEL/CentOS/Fedora (firewalld):**
```bash
sudo firewall-cmd --permanent --add-service=https
sudo firewall-cmd --permanent --add-port=443/tcp
sudo firewall-cmd --reload
```

**Other (iptables):**
```bash
sudo iptables -A INPUT -p tcp --dport 443 -j ACCEPT
sudo iptables-save | sudo tee /etc/iptables/rules.v4
```

### 9. Configure SELinux (RHEL/CentOS/Fedora only)

If SELinux is enabled:
```bash
# Allow Apache to make network connections
sudo setsebool -P httpd_can_network_connect 1

# Allow Apache to connect to Node.js port
sudo semanage port -a -t http_port_t -p tcp 3000
```

### 10. Ensure Node.js Application is Running

**If using systemd service:**
```bash
sudo systemctl status dependability
sudo systemctl start dependability
sudo systemctl enable dependability
```

**If running manually:**
```bash
cd /path/to/dependability-tracker
npm start &
```

Verify it's running:
```bash
netstat -tlnp | grep :3000
# or
curl http://localhost:3000
```

### 11. Start/Restart Apache

**Ubuntu/Debian:**
```bash
sudo systemctl restart apache2
sudo systemctl enable apache2
sudo systemctl status apache2
```

**RHEL/CentOS/Fedora:**
```bash
sudo systemctl restart httpd
sudo systemctl enable httpd
sudo systemctl status httpd
```

### 12. Verify Apache is Listening on Port 443

```bash
sudo netstat -tlnp | grep :443
# or
sudo ss -tlnp | grep :443
```

### 13. Test Access

**From the local server:**
```bash
curl -k https://localhost
```

**From VPN client:**
```bash
# Replace with your actual domain or IP
curl -k https://dependability-tracker.yourdomain.com
# or
curl -k https://10.x.x.x
```

**In browser (from VPN):**
- Navigate to `https://dependability-tracker.yourdomain.com`
- Or `https://10.x.x.x`

### 14. Check Logs if Issues Occur

**Apache logs:**
```bash
# Ubuntu/Debian
sudo tail -f /var/log/apache2/dependability-tracker-error.log
sudo tail -f /var/log/apache2/dependability-tracker-access.log

# RHEL/CentOS/Fedora
sudo tail -f /var/log/httpd/dependability-tracker-error.log
sudo tail -f /var/log/httpd/dependability-tracker-access.log
```

**Node.js logs (if using systemd):**
```bash
sudo journalctl -u dependability -f
```

**Node.js logs (if manual):**
```bash
cd /path/to/dependability-tracker
tail -f log
```

## Common Issues and Solutions

### Issue: 502 Bad Gateway

**Cause:** Node.js application not running or wrong port

**Solution:**
```bash
# Check if Node.js is running
netstat -tlnp | grep :3000

# Start if not running
sudo systemctl start dependability
# or
npm start
```

### Issue: Connection Refused from VPN

**Cause:** Firewall blocking port 443 or wrong VPN subnet in Apache config

**Solution:**
```bash
# Check firewall
sudo ufw status  # Ubuntu/Debian
sudo firewall-cmd --list-all  # RHEL/CentOS

# Verify Apache VPN subnet matches your VPN
ip addr show | grep tun  # Find your VPN IP
# Update Apache config with correct subnet
```

### Issue: SSL Certificate Error

**Cause:** Certificate path incorrect or certificate expired

**Solution:**
```bash
# Verify certificate exists
ls -la /path/to/ssl/certificate.crt

# Check certificate validity
openssl x509 -in /path/to/ssl/certificate.crt -text -noout

# Regenerate self-signed cert if needed
npm run genTLS
```

### Issue: SELinux Permission Denied (RHEL/CentOS)

**Cause:** SELinux blocking Apache proxy connections

**Solution:**
```bash
sudo setsebool -P httpd_can_network_connect 1
sudo semanage port -a -t http_port_t -p tcp 3000
```

### Issue: Apache Config Test Fails

**Cause:** Syntax error in configuration file

**Solution:**
```bash
# Test and see specific error
sudo apache2ctl configtest  # or apachectl

# Check for:
# - Missing modules
# - Incorrect directives
# - Typos in paths
```

## Verification Checklist

- [ ] Apache installed and running
- [ ] Required Apache modules enabled
- [ ] SSL certificates configured
- [ ] Apache virtual host configuration created and customized
- [ ] Firewall allows port 443
- [ ] SELinux configured (if applicable)
- [ ] Node.js application running on correct port
- [ ] Apache listening on port 443
- [ ] Can access application from VPN
- [ ] Logs show no errors
